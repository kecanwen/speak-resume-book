## 重点项目

### 一 · 收钱吧百万商户级 C 端点餐与外卖小程序架构

**项目背景：** 收钱吧扫码点餐与校园外卖小程序覆盖全国 80 万+ 异构商户，日均支撑千万级 PV 流量。由于下沉市场千元级安卓机占比高（超过 40%），且地下档口弱网普遍，随着多规格菜品、阶梯满减、充值营销等复杂能力堆叠，小程序暴露出多业务线并行研发阻塞、低端机掉帧、深层页面栈内存溢出闪退、首屏冷启动慢等底层工程难题。

#### 1. 跨业务线微模块 NPM 分发与多仓库小程序高效联调体系

- **技术难点：** 点单、校园外卖、营销、广告四条核心业务线长期共存于单体小程序仓库，代码冲突频发且发版周期相互阻塞；
- **解耦架构：** <Q id="p1-npm" level={3}>主导“基座宿主小程序 + 业务独立 NPM 子包”解耦架构</Q>。宿主小程序沉淀协议层与公共 SDK，各业务线剥离为独立 Git 仓库在私有 NPM 发布，并在构建期动态编译注入小程序分包；
- **攻克本地联调死穴：** 针对微信开发者工具对软链接（Symlink）支持缺陷导致的文件 Watch 失效与寻址崩溃，自研构建 CLI 工具。为子包提供轻量 Mock 宿主沙箱，支持单业务脱离主工程独立开发；<Q id="p1-cli" level={2}>在宿主模式下，通过构建流 Alias 劫持将 NPM 依赖无感重定向至本地源码物理监听，实现业务包改动 1 秒内触发微信开发者工具热重载</Q>，彻底打断发版阻塞。

#### 2. 小程序路由拦截与并行数据预拉取流水线

- 针对扫码点餐“代码包下载 → 基础库容器启动 → 页面 onLoad 挂载 → 发起网络请求”的传统串行瀑布流，在全局路由守卫层建立网络请求与小程序容器生命周期并行化管道（Pre-fetch Pipeline）；
- 扫码解析商户与桌号后，在页面组件编译前置提前并发拉取菜单与核心券列表，将网络往返耗时（RTT）与容器启动耗时重叠并行化，<Q id="p1-prefetch" level={3}>首屏关键满屏时间（T2）从 3.5s 压缩至 1.1s，扫码后跳失率降低 22%</Q>。

#### 3. 小程序双线程 setData 序列化通信堵塞治理

- 针对用户高频加购时，全量更新导致千元机单次 JSBridge 序列化耗时超 120ms、数据包突破 300KB 导致列表滑动掉帧的痛点，<Q id="p1-setdata" level={3}>自研基于路径 Diff 的局部更新器（Path-based Granular Setter）</Q>；
- 逻辑层维护不可变状态快照，仅向渲染层定向派发扁平化变更路径（如 `cart.items[3].qty`），并结合 16ms 帧生命周期调度器进行操作合并与批量推送；单次通信数据量由 300KB+ 降至 2KB 以内，低端机连续加购帧率稳定在 55 FPS 以上。

#### 4. 深层页面栈内存泄漏与位图内存优化

- 针对点餐“店铺列表 → 菜单 → 菜品详情 → 领券 → 订单确认”多层页面栈跳转导致的内存暴涨，封装生命周期自动化注销器，在页面 onUnload 时强制断开全局 EventBus 与跨包状态监听，阻断闭包泄漏；
- 针对商户上传菜品原图导致的位图解码内存爆炸，构建小程序端专用图片组件，结合 CDN/OSS 视口尺寸动态计算并下发降采样裁剪参数（避免 2000px 大图加载到 80px 容器中），<Q id="p1-oom" level={2}>长时间浏览内存占用降低 45%，线上 OOM 崩溃率下降 70%</Q>。

#### 5. 地下弱网环境下的 SWR 快照秒开与时序竞态控制

- 针对档口弱网，引入 Stale-While-Revalidate（SWR）机制，利用本地 `wx.setStorage` 缓存快照在 100ms 内秒开可交互菜单，后台静默差量更新最新库存与券资产；配合<Q id="p1-swr" level={2}>基于单调递增版本号的时序控制器，阻断弱网并发改单请求后发先至（Race Condition）导致的算错钱事故</Q>。

### 二 · 益丰加盟商多租户自主营销中枢与清结算平台

**项目背景：** 益丰加盟店为独立核算法人，直营营销无法满足加盟商的微观竞争与让利诉求。系统需要支持加盟商自主配置活动、总部进价毛利底线强拦截，以及加盟商、总部、药企三方的补贴对账分摊。本人作为全栈工程师负责该系统在 Java / Spring Boot 企业级体系下的核心业务逻辑开发与前端闭环上线。

#### 1. 统一架构与 Nacos 动态配置化体系

- 前端采用 React + TypeScript，后端基于 Java 17 + Spring Boot + MyBatis-Plus + MySQL；
- 引入 Nacos 作为注册配置中心，将各区域药品的医保控费限价、加盟商毛利红线阈值（如不同慢病类目的 5%–15% 安全底线）集中托管于 Nacos，<Q id="p2-nacos" level={1}>支持运营人员无需重新发版即可秒级动态更新下发生效</Q>。

#### 2. 多租户数据隔离与 Redis 高并发防超发治理

- 在 MySQL 数据库设计中引入 `tenant_id` 租户字段，<Q id="p2-tenant" level={3}>利用 MyBatis-Plus 拦截器（TenantLineInnerInterceptor）在 SQL 执行层面自动拼接租户过滤条件</Q>，实现加盟商间活动规则、会员资产的严密逻辑隔离；
- 针对热门立减券的秒杀与高频领用，<Q id="p2-redis" level={2}>基于 Redis + Redisson 分布式锁与 Lua 脚本实现库存的原子预扣减与校验，杜绝卡券超发风险</Q>；同时将加盟药品供货批发价缓存至 Redis，大幅降低数据库 I/O 穿透。

#### 3. 进价毛利底线风控拦截引擎

- **业务痛点：** 避免加盟商盲目降价打折导致售价击穿向总部的批发进货成本，引发经营纠纷；
- **后端实现：** 在营销活动创建的 Service 层构建风控拦截链。活动提交时，Service 自动拉取关联药品的采购批发价与出库成本，<Q id="p2-margin" level={3}>解算多阶梯折扣下的临界最低毛利率</Q>；若出现负毛利或低于安全阈值，直接抛出业务自定义异常（BizException）拦截并返回亏损测算明细，前端精准高亮阻断提交。

#### 4. RocketMQ 异步解耦与补贴对账“进货款抵扣”闭环

- **核销解耦：** 线下门店高频核销营销券产生大量流水，利用 RocketMQ 消息队列进行异步削峰解耦，消费端异步处理“总部补贴、加盟商自贴、药企让利”三方资金拆解与分摊抹零；
- **最终一致性结算：** <Q id="p2-mq" level={2}>结合 RocketMQ 事务消息对接加盟供应链 ERP 的“采购应付账单”，确保活动补贴凭证生成与加盟商下次采购请货款抵扣达到分布式最终一致</Q>，杜绝财务跨期对账误差。

### 三 · 加盟数字化工作台 AI-Native UI 自动化测试与自愈系统

**项目背景：** 益丰加盟数字化工作台涵盖请货、商品、营销、供应链等多条复杂业务线，周均迭代频繁。传统基于 Playwright / Appium 的 UI 自动化测试面临三大痛点：① 需求变更频繁导致 XPath/元素选择器大面积断裂（单次迭代 20%+ 用例失效）；② 测试用例平台积累的大量自然语言描述用例无法直接执行，转化成本高；③ 弹窗遮挡、流程微调引发用例频繁挂掉，人工排查调试成本高昂。为此参考业界前沿（如得物 AI UITester）架构理念，从 0 到 1 主导搭建了 AI-Native 的视觉驱动自动化测试体系。

#### 1. 测试范式重构：从“代码选择器驱动”转向“多模态视觉驱动”

- 彻底摒弃对 DOM 树、XPath、Accessibility ID 等底层脆弱定位器的依赖；
- 接入视觉大语言模型（VLM），建立跨平台视觉操作抽象层。系统直接对端侧截屏进行多模态空间感知与视觉语义对齐，像真实用户一样基于画面文案、图标相对位置进行语义 Grounding（识别按钮与输入框并执行点击/滑动），<Q id="p3-vlm" level={3}>从根源上免疫前端组件重构与嵌套层级变更引发的脚本断裂</Q>。

#### 2. 描述性用例自动化转化流水线（Pipeline + LLM 增强）

- 针对内部用例平台导出的树形结构用例数据，构建自动化解析与增强流水线：
  - Phase 1–3：树结构展平、叶节点面包屑路径解析与已有用例去重；
  - Phase 4（LLM 增强）：利用结构化 Prompt 注入业务 Wiki 知识，将模糊描述（如“选择降压药并提交请货单，验证状态流转”）自动编译为规范的原子步骤序列（App / Tap / Wait / Input / Assertion）；
- 结合校验器兜底降级策略，<Q id="p3-pipeline" level={2}>实现 90% 历史文本用例零人工干预自动转化为可执行脚本</Q>。

#### 3. AI 智能诊断与动态“失败自愈（Self-Healing）”引擎

- **分流拦截：** 设计规则过滤层，优先过滤网络超时、设备掉线等非业务异常自动重试，仅将页面级非预期失败送入 AI 诊断模块；
- **执行指针回退与动态修补：** 当遇到“版本更新弹窗遮挡”、“营销活动弹窗拦截”或“操作步骤微调”时，VLM 结合预期与实际截图进行多轮因果推断；诊断出遮挡原因后，动态将执行指针回退至上一步，并在执行流中自动插入前置条件 Action（如点击遮罩关闭弹窗）；
- 自愈引擎输出完整步骤修正列表，<Q id="p3-heal" level={3}>在无人介入下实现 60% 的业务执行失败自动修复与用例自愈</Q>。

#### 4. 架构取舍与防误触守门体系（Guardrails）

- **逐步执行（Step-by-step Execution）：** 放弃脆弱的一次性长序列规划，采用单步执行 → 截屏 → 决策的动态反馈循环，平衡 UI 状态的不确定性；
- **置信度调优与逐字校验：** <Q id="p3-guard" level={2}>实测将 VLM 操作置信度阈值锁定在 0.5，在误操作率与通过率间取得最佳平衡</Q>；制定铁律约束——MatchedText 必须从截图中逐字符精准提取匹配，杜绝大模型臆造，做到“宁可跳过报错，绝不盲目误点”。

#### 5. 工程收益

- 该体系在加盟工作台核心回归链路落地后，跨端自动化测试脚本日常维护人力成本降低 75%；
- 每次发版回归测试执行耗时从 3 人天缩减至 2 小时自动化流水线巡检，<Q id="p3-value" level={1}>线上前端交互 Bug 漏测率下降 40%</Q>，成为研发效能基础设施标杆。
