这道题我会按四块讲：双线程由谁组成、为什么要这样设计、数据怎么跨线程走，以及后来为什么会演进到 Skyline。

微信和支付宝等主流小程序的双线程架构，是指将渲染层（View）与逻辑层（AppService）彻底拆分，并运行在两个独立线程（或进程/运行环境）中的底层设计。

## 一、双线程架构的核心组成

1. **渲染层（View / UI 线程）**
   - **运行环境：** 基于浏览器的 WebView（iOS 中通常为 WKWebView，Android 中为系统内核或 X5 内核）。
   - **主要职责：** 负责页面的展示、WXML 结构解析、WXSS 样式计算、布局排版及绘制。一个页面通常对应一个独立的 WebView 实例。
   - **限制：** 不能直接运行 JavaScript 业务逻辑代码。
2. **逻辑层（AppService / JS 线程）**
   - **运行环境：** 独立于 WebView 的 JavaScript 引擎（如 iOS 的 JavaScriptCore、Android 的 V8 或 Hermes 等）。
   - **主要职责：** 负责小程序的业务逻辑、数据处理、API 调用（如网络请求、本地存储、扫码、支付等）以及生命周期管理。
   - **限制：** 没有 DOM / BOM 接口，无法直接接触和修改页面 UI。
3. **Native（客户端宿主环境 / 微信或支付宝 App 原生层）**
   - 充当中转站与调度中心。
   - 负责两个线程之间的通信桥梁（JSBridge）、系统级 API 调用、原生组件（如相机、地图、输入框）的渲染以及网络请求的实际转发。

## 二、为什么设计成双线程？

与传统 Web 开发（JS 与 DOM 共享同一个主线程，容易因复杂的 JS 计算导致页面卡死、掉帧）不同，小程序引入双线程主要为了解决以下痛点：

1. **性能与流畅度（避免 JS 抢占 UI 渲染资源）**
   - 在传统 H5 中，如果 JS 执行大量复杂运算，会阻塞主线程，导致 UI 动画和页面滑动卡顿。
   - 双线程下，JS 计算在逻辑层线程，UI 绘制在渲染层 WebView，两者互不阻塞，保证了滑动和动画的流畅性。
2. **安全管控（沙箱隔离）**
   - 传统浏览器中，JS 可以随意获取或篡改 DOM、通过 `window.location` 任意跳转，或者通过 Cookie 获取敏感信息。
   - 小程序逻辑层运行在独立的 JS 引擎沙箱中，没有 DOM 接口，无法直接操作页面元素，必须通过 Native 中转，杜绝了网页脚本注入（XSS）等安全风险。
3. **加载与更新机制（分包与动态加载）**
   - 渲染层多个页面由多个 WebView 承载，页面切换时直接覆盖或滑动，体验更接近原生 App。

## 三、底层工作流程与通信机制

因为逻辑层和渲染层运行在不同的线程，它们无法共享内存，所有的交互必须通过 Native 层进行序列化与反序列化的异步通信（JSBridge）：

1. **首屏渲染流程**
   - 逻辑层和渲染层同时开始初始化。
   - 逻辑层加载完 JS 代码，运行 `App()` 和 `Page()`，算出初始数据 `data`。
   - 逻辑层通过 JSBridge 将初始数据发送给 Native 层，Native 层再转发给对应的渲染层 WebView。
   - 渲染层结合 WXML 和 WXSS，将数据套入模板，最终渲染出首屏画面。
2. **数据驱动与 setData 机制**
   - 当逻辑层数据发生变化时，开发者调用 `this.setData({ key: value })`。
   - 逻辑层将 setData 的数据通过 JSBridge 传给 Native 层，再由 Native 层转交给渲染层。
   - 渲染层收到数据后，对比前后虚拟 DOM（或 JS 对象树）的差异（Diff 算法），局部更新真实的 DOM 树。
   - **代价：** 正因为每次 setData 都要跨线程通信，如果过于频繁或传输超大数据包，会产生明显的通信延迟与性能开销。
3. **用户事件交互流程**
   - 用户在视图层（WebView）点击了某个按钮。
   - 渲染层捕获到该事件（如 `bindtap`），将事件信息（事件类型、组件 id、携带参数等）通过 JSBridge 发送给 Native 层。
   - Native 层转发给逻辑层对应的 JS 回调函数（如 `onTap`）。
   - 逻辑层执行业务逻辑，若需要改变界面，再次调用 setData，形成闭环。

## 四、双线程架构的演进与新趋势（如 Skyline 引擎）

虽然双线程架构带来了安全和流畅度，但也带来了通信开销大、首屏白屏时间较长、复杂手势/动画处理不够丝滑等问题。因此，微信等平台后来也推出了混合/同线程渲染架构（例如微信小程序的 Skyline 渲染引擎）：

- 允许逻辑与视图在一定程度或特定模式下更紧密地结合，甚至支持 Worklet 线程在 UI 线程直接运行部分动画逻辑，以此突破传统双线程在高帧率动画和复杂手势上的性能瓶颈。
