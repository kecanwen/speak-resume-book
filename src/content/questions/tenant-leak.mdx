title: 拦截器自动拼租户条件，有哪些情况会漏掉？
type: principle
short: >-
  主要有三类：手写的复杂 SQL（子查询、联表）解析不到位，异步线程和 MQ 消费里拿不到租户上下文，
  以及本来就该跨租户的总部表被误加条件。我们分别用白名单、上下文透传和集成测试来兜。
followUps: [tenant-why-not-shard]

**租户 ID 从哪来：** 网关解析登录态写入请求头，后端过滤器放进 `ThreadLocal`，拦截器从这里读取。

**容易漏的地方：**

1. **异步与消息消费：** 线程池和 MQ 消费线程里没有请求上下文。我们用装饰过的线程池透传上下文，MQ 消息体里显式带上 `tenant_id`，消费时先设置上下文。
2. **跨租户的表：** 药品主数据、批发价是总部维度的，需要加到忽略表名单里，否则会查不到数据。
3. **复杂 SQL：** 少数手写 SQL 的解析结果不符合预期，这类 SQL 要求显式写租户条件，并在代码评审时重点看。

**兜底：** 集成测试里用两个租户的数据跑核心接口，断言查不到对方的数据。
