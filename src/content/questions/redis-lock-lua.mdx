title: Lua 脚本本身就是原子的，为什么还要 Redisson 分布式锁？
type: challenge
short: >-
  好问题，两者解决的不是同一件事。库存扣减只用 Lua 就够了，不加锁；
  分布式锁用在“一个用户领券”这个跨 Redis 和数据库的复合操作上，防止同一用户并发重复领取，以及缓存失效时重建库存的并发。
followUps: [redis-consistency]
---

我会把两者的边界讲清楚：

- **Lua 负责“库存”：** 在一个脚本里判断库存是否大于 0 并扣减，Redis 单线程执行，天然原子，这一步不需要锁。
- **锁负责“人”和“重建”：**
  - 按 `用户 + 券模板` 加锁，保证同一个用户的“校验限领 → 扣库存 → 写领取记录”整体串行，防止连点或脚本刷券时重复领取。
  - 库存缓存失效时，只允许一个线程从数据库重建，防止缓存击穿。

**反思：** 限领其实也可以塞进 Lua 里（用 Set 记录已领用户），能省掉一把锁。我们当时考虑到领取记录需要落库、要带更多业务校验，才选了加锁。这块如果重做，我会先压测再决定。
