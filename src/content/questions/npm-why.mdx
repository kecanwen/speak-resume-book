title: 为什么不直接用小程序分包或 Monorepo，而要拆成 NPM 子包？
type: tradeoff
short: >-
  小程序分包只解决“包体积”，不解决“发版耦合”——代码还在一个仓库、一条发布流水线上。
  Monorepo 能隔离代码，但四个团队的权限、CI 和节奏还是绑在一起。NPM 子包让每条业务线独立开发、独立测试、按版本号被宿主集成。
followUps: [npm-deps, cli-symlink]
---

当时我们对比过三条路：

- **只用小程序分包：** 体积问题能缓解，但四条业务线还是改同一个仓库，冲突和互相阻塞发版的问题没解决。
- **Monorepo：** 代码边界清楚了，但仓库权限、CI 时长、发布窗口还是共享的。营销和广告迭代特别频繁，会拖住点单主链路。
- **宿主 + NPM 子包（最终选择）：** 宿主只管协议层和公共 SDK，业务包按语义化版本发布，宿主在构建期把它们编译进对应分包。

**放弃了什么：** 本地联调变复杂了（这就是后来要自研 CLI 的原因），以及要维护一套宿主与子包之间的协议版本。我们认为这个成本是一次性的，换来的是发版解耦，值得。
