title: Redis 预扣的库存和数据库怎么保持一致？
type: principle
short: >-
  Redis 是“预扣”，数据库是“实扣”。Redis 扣成功后异步写领取记录到数据库；写库失败就回补 Redis 库存。
  另外有定时对账任务比较两边数量，差异超过阈值就告警并以数据库为准修正。
followUps: [mq-tx, redis-lock-lua]
---

- **正向：** Redis 扣减成功 → 发消息异步落库（领取记录 + 库存流水）。用户侧看到的是“领取成功”，落库是最终一致的。
- **失败回补：** 落库失败（重试耗尽）时，执行回补脚本把 Redis 库存加回去，同时把这条记录标记为失败。
- **对账：** 定时任务比较“Redis 剩余库存 + 数据库已领数量”是否等于总量，不平就告警。
- **原则：** 允许少发（宁可券没发完），不允许超发。

这是一个典型的“缓存扛并发、数据库保正确”的取舍。
