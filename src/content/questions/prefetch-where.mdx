原来的链路是严格串行的：

```
下载代码包 → 启动基础库 → 页面 onLoad → 发请求 → 等响应 → setData → 满屏
```

我们做了三件事，按贡献大小排：

1. **请求前移、与启动并行：** 在 App 启动和全局路由守卫阶段就解析扫码参数（商户、桌号），立刻并发请求菜单和券列表。页面还在初始化时，数据已经在路上了。
2. **主包瘦身：** 业务拆进 NPM 子包和分包后，主包远离 2MB 上限，下载和注入都更快。
3. **SWR 快照：** 老用户再次扫码时，先用本地缓存渲染可交互菜单，后台再刷新。

**口径说明：** T2 指首屏菜单可见可点；以线上性能埋点的 P50 为准，我们也同时看了 P90，主要盯千元机分组。
